AI Notes:

I’d start by clarifying one important domain detail: `users_phrases` currently means “saved by this user,” not “created by this user.”

That means:

- **List:** show phrases through `$request->user()->phrases()->latest()->paginate(15)`.
- **Delete:** detach the phrase from the current user; do not delete the shared `phrases` row.
- **Edit:** currently ambiguous, because editing the phrase changes it for every user who saved it. Either:
  - allow editing only for the original creator by adding ownership metadata, or
  - postpone edit and start with “remove from my phrases.”

For the UI, I agree with your direction: a compact management list rather than the editorial search cards. Each row could contain:

```text
[phrase text]       [author] [tags]       Edit  Remove
```

The first implementation slice should be:

1. Add an authenticated `GET /phrases/manage` route.
2. Add `PhraseManagementController@index`.
3. Paginate only the authenticated user’s phrases.
4. Create a compact Blade view with edit/remove action areas inside each row.
5. Add a `DELETE /phrases/{phrase}` action that detaches only the current user’s pivot record.
6. Add feature tests for authentication, pagination, isolation between users, and removal.

The main files would be `web.php`, a new management controller, a new management view beside `search.blade.php`, and a new feature test.

I would implement the list and remove action first. That gives you a useful `/phrases/manage` page while avoiding a misleading edit operation on shared phrase data.
